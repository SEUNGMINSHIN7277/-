# Phase 8 — 사업계획서 16항목 : HE-Cast

> 수치 "가설" 표기. 출처 URL은 domain_brief.md 참조.

## 1. 한 줄 정의(30초 피치)
"은행이 당신의 개인정보를 **한 번도 들여다보지 않고** 사기를 잡습니다. HE-Cast는 어떤 AI 모델이든 *암호화된 데이터 위에서* 추론하게 자동 변환·배포하는 컴파일러입니다."

## 2. 문제(정량)
- FHE ML 추론은 평문 대비 **약 10^5배** 느림(arXiv 2606.17421) — 핵심 병목은 비선형 함수의 다항 근사로 인한 **곱셈깊이 폭발 → bootstrapping 폭증**. 저차 다항은 정확도 붕괴, 입력범위 이탈 시 발산(arXiv 2404.03216).
- 규제(韓 MyData 2.0 2025.3~, PIPA 전송요구권, EU/美 동조)로 민감데이터 평문 처리 제약↑ → "외부 ML로 안전하게 스코어링"하는 워크플로가 **현재 사실상 불가**.
- 즉, "내 모델→FHE 배포 모델" 자동 변환 + 깊이/정확도 공동최적화 **표준 툴체인 부재**.

## 3. 솔루션(왜 10배)
- (a) Depth-Accuracy 공동최적화 컴파일러 (b) Bootstrap 최소 스케줄러 (c) 입력분포 인지 적응 다항 라이브러리. → 동일 정확도에서 **bootstrap/지연/비용 10x↓(가설)**. bootstrapping이 비용 지배항이라는 제1원리로 직접 절감.

## 4. 왜 지금
- GPU CKKS 70x bootstrapping(FIDESlib 2025), HEIR IR(2024), Orion 자동 bootstrap 배치(2025) — *재료가 막 갖춰짐*. 동시에 MyData 2.0·혁신금융샌드박스 520건+로 **규제 강제 수요 폭발.** 큰 플레이어(Zama)는 블록체인으로 비켜남 → ML 컴파일러 빈틈.

## 5. 차별성·해자
- 모트=알고리즘·수학(주말 복제 불가) + FHE-Bench 데이터 플라이휠 + 특허 청구항 3종 + 규제·금융 도메인 적합. Zama=블록체인/저수준, Duality=MPC/대기업SI, IBM=연구. **"일반 ML팀용 깊이최적 FHE 컴파일러+서빙" 포지션 비어 있음.**

## 6. 시장 TAM/SAM/SOM (가설·출처)
- TAM: 프라이버시 보존 ML USD 3.82B(2025)→15.91B(2030, CAGR 32.9%). (360iResearch)
- SAM(가설): 금융·의료 암호화 추론/협업분석 글로벌 ~USD 1.5B(2030).
- SOM(가설): 韓 금융·의료 PoC·라이선스 초기 3년 누적 ~USD 15~30M 타깃.

## 7. 수익모델·단위경제(가격/원가/마진/BEP, 가설)
- 유상 PoC 3,000만~5,000만원/건(초기 현금흐름).
- 본계약: ① 컴파일러 라이선스(연 1~3억원/엔터프라이즈) ② 추론 처리량 과금(암호문 추론 건당, GPU 원가 위 고마진 SW).
- 마진: SW 80%+ (GPU 클라우드 변동비 차감 후). BEP: 18~24개월(가설, PoC 6~10건 + 본계약 2~3건).

## 8. GTM(초기고객 10곳·파트너·해외)

- 동반전략: **혁신금융서비스 샌드박스 공동신청**으로 규제 클리어 + 레퍼런스.
- 파트너: OpenFHE/FIDESlib(오픈소스), GPU 클라우드(NCP/AWS), 경기도 핀테크·판교 채널.

- 12mo: bootstrap 스케줄러+적응 다항 라이브러리, 정확도 손실 <1%p·bootstrap 대비 기준 측정. 은행/핀테크 유상 PoC 1~2건.
- 18mo: 멀티-GPU 서빙 베타, FHE-Bench 공개(데이터 해자), 본계약 1건 + 샌드박스 진입. (24mo: 수직 확장·LLM 로드맵 착수.)
