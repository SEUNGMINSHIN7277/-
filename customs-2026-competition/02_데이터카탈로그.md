## B. 관세청 수출입무역통계 누리집(tradedata.go.kr)

- **2023.9.20 리뉴얼** — 기존 `unipass.customs.go.kr/ets`(전자통관시스템 내 통계메뉴)를 대체하여 별도 사이트로 독립. 기존 **46종 → 94종**으로 통계 확대(세수통계·FTA활용률 등 추가). 5개 이상 언론사·정책브리핑 공식 보도자료로 교차확인됨(신뢰도 높음).
- 제공 통계군: 국가별/품목별/시도별/세관별/성질별/신성질별/종류별/경제권별/대륙별/항구공항별 수출입실적, 수출입총괄, 무역수지, 관세수입통계, FTA활용률 등. 복수 국가·복수 품목 동시 조회, 막대/원/지도/히트맵 시각화 제공.
- **중요**: tradedata.go.kr 사이트 자체는 조회용 웹 UI이며, **오픈API 인증키 발급은 tradedata.go.kr이 아니라 공공데이터포털(data.go.kr)에서** 이뤄짐 → 기획서에 "tradedata.go.kr API 활용"이라고만 쓰지 말고, 실제로는 data.go.kr에 등록된 위 표의 API(국가별/품목별 수출입실적, 10일단위 잠정치 등)를 지칭하는 것임을 명확히 할 것.
- 관세청 빅데이터 포털(`bigdata.customs.go.kr`)은 **2022년 6월 22일 개통**(주의: 여러 자료에 2023년으로 잘못 인용된 경우가 있으니 기획서엔 2022년으로 기재). 3대 기능: 맞춤형 지원사업 안내·유사 품목분류 사례 제공·수출입 트렌드 분석.

## C. 국가관세종합정보시스템 UNI-PASS (unipass.customs.go.kr)

- 브랜드 성격: 통관·화물·징수 등 업무처리 정보시스템 총칭(전자신고/전자납부/업무지원/정보조회/통관단일창구/AEO 등). Open API는 회원가입 후 **My메뉴 > 서비스관리 > OpenAPI 사용관리**에서 신청 시 즉시 승인, 인증키(`crkyCn`) 발급.
- REST 엔드포인트 패턴(GitHub 오픈소스 라이브러리로 코드 레벨 확인, 신뢰도 높음): `https://unipass.customs.go.kr:38010/ext/rest/{서비스ID}/{오퍼레이션}?crkyCn=...`
  - **화물통관 진행정보 조회**: `cargCsclPrgsInfoQry/retrieveCargCsclPrgsInfo` — 파라미터 `cargMtNo`(화물관리번호)/`mblNo`/`hblNo`/`blYy`/`crkyCn`
  - **수출신고번호별 수출이행내역 조회**: `expDclrNoPrExpFfmnBrkdQry/retrieveExpDclrNoPrExpFfmnBrkd` — 파라미터 `expDclrNo`(수출신고번호), 응답필드 `tkofDt`(출항일자)/`shpmWght`(선적중량)/`csclWght`(통관중량) 등
- **관세환율정보(GW)** (data.go.kr 15101230): 국가부호/화폐단위명/환율/통화부호/적용개시일자. ⚠ 유사 구버전 데이터셋(15070433)이 병존 확인 — 응모 전 최신 버전 확인 필요.
- **세관장확인대상물품(GW)**: 위 A표와 동일 데이터, UNI-PASS 경로로도 노출.
- **개인통관고유부호(P-code) 유효성 검증 API** (`persEcmQry/retrievePersEcm`): 전자상거래 개인수입 필수 정보. **2024.4.6부터 정책 대개편** — 신규 발급 신청 중단, 조회 시 성명+휴대전화번호 전체 일치 필수, 사업자만 신규 신청 가능. **2026.2.2부터 우편번호까지 일치 요구**, **2026.1.1부터 유효기간 1년제(매년 갱신)** 도입 확인 — 개인통관 관련 아이디어를 낸다면 이 최신 규정 변화를 반드시 반영할 것(구정보 기반 기획은 감점 리스크).
- "UNI-PASS 오픈API 총 30건" 이라는 수치는 단일 출처(cloudlog.kr) 재인용 의혹이 있어 **불확실** — 정확한 현재 API 종수는 로그인 후 직접 확인 권장. 또한 관세청이 과거 일부 API를 폐기/대체한 이력이 존재하므로, 오래된 블로그 글의 API 목록을 그대로 신뢰하지 말 것.

## D. 실무 팁 — 데이터 접근 시 유의사항

1. **정부 도메인은 자동 크롤링/봇 접근에 막힌다.** 반드시 사람이 직접 로그인해서 최신 스펙(Swagger, 요청변수, 응답 스키마)을 확인해야 한다 — 이는 실제 개발 착수 시에도 마찬가지이므로 기획서에 "API 신청 및 인증키 발급 절차까지 검토 완료"라고 쓰면 구체성 점수에 유리.
2. **유사 데이터셋 난립**(면세점 매출, 관세환율정보 등) — 응모서에 데이터셋명을 쓸 때 정확한 최신 ID/게시일자를 확인해서 기재할 것. 오래된 자료를 베끼면 실현가능성 항목에서 감점 요인.
3. **"(GW)" 표기 데이터셋** 중 일부(품목별 국가별 수출입실적)는 표준 오픈API 호출 목록이 아니라 별도 접근경로로 분류되어 있을 가능성 — 실제 신청 화면에서 호출 가능 여부를 반드시 확인.
4. **tradedata.go.kr ≠ 별도 오픈API 서버.** 통계 조회 UI는 tradedata.go.kr, API 인증키 발급은 data.go.kr — 이 구조를 정확히 이해하고 기획서에 반영하면 "공공데이터 및 AI기술 활용"(25점) 항목에서 신뢰도를 높일 수 있음.
