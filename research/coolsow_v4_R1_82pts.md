# 쿨소(CoolSow) — 축산 폭염 열스트레스 위험지수 + 개입 트리아지 의사결정 플랫폼
팀 theOne / 부문: 아이디어 기획

---

## 1. 문제

2024년 전북 폭염 가축폐사는 최종 38.3만마리·890농가·피해액 48.36억원으로 2023년 대비 2.6배 급증했다. 2025.7.25 기준 잠정 16.6만마리로 전국 2위 피해규모를 이미 기록 중이며, 폐사의 88%가 닭(육계·산란계)에 집중된다. 피해는 균질하지 않고 시군에 편중된다(정읍 4.4만·남원 2.7만·익산 2.5만·김제 1.8만마리). 즉 문제의 본질은 "폭염이 온다"가 아니라 "한정된 방역차·급수차·쿨러 자원을 890개 넘는 농가 중 어디에 먼저 보낼 것인가"라는 배분 문제이며, 이 배분을 잘못하면 동일한 예산으로 회피 가능했던 손실을 회피하지 못한다.

쿨소는 이 배분 문제에 답하기 위해 공공데이터 4중결합(기상 단기예보 15084084 / AWS 15057084 / ASOS 15057210 + 가축사육현황 15021089·15072592 + 익산 축산농가 15140402 + 국토부 건축물대장 15134735)을 사용해 "오늘 어느 축사부터 조치해야 하는가"를 매일 아침 산출하는 플랫폼이다.

## 2. 활용데이터

### 2.1 데이터-수식 매핑: 4종 결합의 필요성-충분성 증명

쿨소의 핵심 산출식은 기대회피손실 함수다.

**E[Loss_i] = N_i × p(THI*_i | T, RH) × f(structure_i)**, 위치 인덱스 i = 축사(익산 축산농가 15140402 좌표 조인 키)

이 식의 3개 항과 1개 인덱스는 4종 공공데이터에 1:1로 대응하며, 어느 하나가 빠지면 "데이터가 조금 부실해진다"가 아니라 해당 항이 **수학적으로 미정의되거나 전 축사 동일값으로 붕괴**한다.

| 데이터셋(ID) | 수식 대응 항 | 결측 시 붕괴 결과 |
|---|---|---|
| 기상 3종(15084084/15057084/15057210) | p(THI*) — 위험강도 | T, RH 없이 THI 자체가 정의 불가. 비-AI 물리식 계산이 원천 불능(대체 데이터 없음) |
| 가축사육현황(15021089/15072592) | N_i — 규모 | THI로 위험 "여부"는 알아도 "몇 마리가 위험한가"라는 절대량을 산출 불가 |
| 건축물대장(15134735) | f(structure_i) — 구조보정 | f=1로 고정되어 전 축사가 동일 위험도로 취급됨(아래 2.2 참조) |
| 익산 축산농가(15140402) | 위치 인덱스 i | 축사 단위 결합 자체가 불가능, 시군 평균값으로 뭉개짐(2.3 참조) |

### 2.2 건축물대장이 왜 필요한가 — 최소반례 1문장

"정읍 A농가와 B농가가 동일하게 육계 3만수를 사육하고 동일 AWS 관측소 반경 5km 내에 위치해 동일 THI를 적용받더라도, A는 2015년 이후 신축된 무창(밀폐형) 계사이고 B는 1990년대 개방형 슬레이트 계사라면 실효 열스트레스는 2~3배 차이가 나며, 건축물대장의 사용승인일·구조·지붕재질 정보 없이는 방역차·급수차를 어느 농가에 먼저 보낼지 구별할 방법이 원천적으로 없다."

동일 두수·동일 기상이라도 구조가 다르면 순위가 갈린다 — 이것이 건축물대장을 "부가정보"가 아니라 "구조보정 항 f(structure_i)의 유일한 원천"으로 만드는 이유다.

### 2.3 익산(농가단위) vs 13시군(시군집계) 정밀도 비교

| 구분 | 익산(즉시실증) | 13시군(편입 단계) |
|---|---|---|
| 공간단위 | 축산농가별 지번 단위(건축물대장 1:1 조인) | 시군/읍면동 집계치 |
| 구조보정 | 실제 사용승인일·구조·층수 기반 f(structure_i) 개별값 | 축사 유형별 표준계수(2.4 계수표)로 대체 |
| 폐사 검증 | 시군 방역과 실사 폐사신고와 매칭 가능 | 전북도 집계 통계(정읍 4.4만·남원 2.7만 등)로 대체 |

정밀도 손실은 공간해상도로 약 "농가단위 → 읍면동/시군단위" 1~2단계 저하로 요약된다. **13시군 대체로직**: 건축물대장 개별조인이 지연되는 시군은 축사 유형(가설건축물대장 코드 또는 농림축산식품부 표준축사유형)별 평균 환기계수를 잠정 적용하고, 익산 실증에서 산출된 유형별 계수를 사전분포(prior)로 이식한다.

### 2.4 환기부하 매핑 계수표

건축물대장의 주용도(축사)+구조+지붕재질+사용승인연도를 조합해 4등급, THI\* = THI_ASOS보정 + ΔT_구조:

| 등급 | 조건 | ΔT_구조 |
|---|---|---|
| A(밀폐형 무창) | 강제환기팬+쿨링패드, 2015년 이후 승인 | −1.5℃ |
| B(터널식 자연환기) | 측벽커튼, 2000~2014년 승인 | +0.5℃ |
| C(개방형 우사/계사) | 조적조·슬레이트, 1999년 이전 승인 | +2.0℃ |
| D(무허가·미등록·매칭실패) | 건축물대장 미조회 또는 컨테이너·가설건축물 | +3.0℃(보수적 상한) |

*출처: RDA(농촌진흥청) 축사시설 환기효율 관련 보고서 계수 준용 예정 — 보고서명·연도·표본수는 제출 전 1차출처 확인 필요. 익산 실증 표본으로 재보정 예정.*

### 2.5 축종별 데이터 세분화

가축사육현황(15021089/15072592)에서 닭(육계/산란계 구분 코드)·오리·한육우 필드를 분리 추출해 N_i를 축종별로 분리하고, 이 필드 분기가 AI혁신성 섹션(6.1)의 가금 특화 THI 임계치 분기와 직결되도록 공공데이터 단에서 선결처리한다. 이는 "폐사 88%가 닭"이라는 문제정의와 사육현황 데이터 활용을 논리적으로 봉합한다.

### 2.6 옥외관측 → 옥내환경 대체의 정당화

ASOS/AWS는 옥외관측이므로 축사 내부(옥내) 환경으로의 직접 대입은 인과적 비약이다. 쿨소는 이 간극을 "옥외 THI + 건축물대장 기반 구조보정 ΔT_구조"로 명시적으로 메운다(2.4). 즉 옥외 THI는 입력항일 뿐이고, 실제 리스크 판단은 옥내 환경을 근사하는 THI\*(구조보정 후 값)로 이루어진다는 점을 논리 골격으로 못박는다.

### 2.7 무허가·미등록 축사 결측 보완

건축물대장 매칭 실패(등급D)는 자동으로 ΔT=+3.0℃ 보수적 상한을 적용하되, 위치·규모는 위성영상(국토위성·농림위성 정사영상) 폴리곤 추출 또는 농협 사육신고자료(신고두수)로 2차 대체한다. 결측 자체를 숨기지 않고 리스크 신호로 처리한다.

## 3. 독창성

### 3.1 경쟁 스펙 대비 3갭

| 구분 | 제공 기능(공개 스펙 기준) | 답하지 못하는 질문 |
|---|---|---|
| 축사로(팜모닝 등 스마트팜 통합앱 계열) | 농장 단위 폭염주의보 알림 + 생산성 예측 | "오늘 890개 농가 중 어디부터, 무엇을 보낼까"에 답 불가(축사 내부 실측센서 없이는 개체 위험량 미산출) |
| 민간 개체관리(한국축산데이터 팜사인=반추가축 데이터 표준화 허브, 인트플로우=CCTV 비전 AI 개체 이상탐지, 바딧=유통·이력관리) | 개체·사양 데이터 수집·표준화 | 시군 단위 자원배분 의사결정 자체를 만들지 않음(개체관리≠자원배분) |
| 가축재해보험(NH농협손보 등) | 폐사 발생 **후** 손해사정·보상금 산정 | 사전 개입 트리거가 없어 "폐사 전에 무엇을 할지"에 답 불가 |

*위 3개 서비스 기능 스펙은 공개 웹페이지/앱스토어 설명 기준 2차 인용이며, 제출 전 1차 출처(공식 사이트 캡처 또는 담당자 확인) 재검증 필요.*

**키프리스 검색 방법론**: (축사 OR 축사시설) AND (폭염 OR 열스트레스) AND (트리아지 OR 자원배분 OR 우선순위) AND (건축물대장 OR 축사구조), IPC A01K1/00(축사 일반)·G06Q50/02(농업 정보처리) 교차조회. 2026.7.1 기준 동일 조합의 선행 등록/공개특허 미발견(검색 스크린샷 별첨 예정). 단 이는 "독창성 입증"이 아니라 "진입장벽 부재의 확인"으로만 해석하며, 제안서 표현도 "독창적이다"가 아니라 "2026.7.1 키프리스 검색 기준 동일 조합의 선행특허 미확인(1차 확인 필요)"으로 정정한다.

가치사슬 관점에서 왜 시군 축산과가 1차 채택자인가: 재해 **전** 개입은 B2G(공공 방역) 영역이고, 재해 **후** 보상은 B2B(보험) 영역이다. 쿨소는 전자에 위치하므로 보험사가 아니라 시군 축산과가 자연스러운 1차 고객이다. (보험 언더라이팅 연계는 사후 영역이므로 독창성이 아닌 발전가능성 섹션으로 이관 — 5.4 참조.)

### 3.2 트리아지는 곱셈결합이 아니라 새로운 문제 클래스다

결정변수 x_{i,k} ∈ {0,1} (축사 i에 자원종류 k(방역차/급수차/쿨러) 배정 여부).

**목적함수**: max Σ_i Σ_k x_{i,k} · ΔL_{i,k} (ΔL_{i,k} = 자원 k 투입 시 축사 i의 기대회피손실, 2단 베이지안 신뢰구간 하한을 사용해 보수적으로 배정)

**제약**:
1. Σ_i x_{i,k} ≤ C_k (자원 k의 가용 대수/1회 capacity)
2. Σ_k x_{i,k} ≤ 1 (축사당 중복배정 방지 또는 자원조합 규칙)
3. travel_time(depot, i) ≤ T_max (골든타임 제약)
4. 동률(ΔL 동일) 처리: 사육두수 내림차순 → 축사 THI\* 내림차순 순차 적용

곱셈 랭킹(THI×두수 정렬)은 자원 제약이 없는 순수 정렬 문제(풀이 자체가 자명함)인 반면, 위 정식화는 배낭/할당 문제로 자원이 부족할 때 최적해가 랭킹 top-N과 달라진다. 예: 축사 3개, 자원 2대인 경우 회피손실 1위 축사가 이동거리 초과로 배제되고 3위+5위 조합이 총회피손실 면에서 더 우수할 수 있다 — 이 수치 반례는 완성도 섹션(4.2)의 시뮬레이션 표와 연동한다.

### 3.3 왜 아무도 이 결합을 안 했나 — 구조적 해자

- **데이터 접근성 장벽**: 익산 축산농가 데이터셋(15140402)은 시군 단위 개별 공개이며, 13시군 전체 편입은 시군마다 컬럼 스키마·갱신주기가 달라 담당공무원 협조 기반 개별 ETL이 필요하다. 익산 실증 경험 자체가 "13시군 확장 표준 매뉴얼"이라는 자산이 된다.
- **협업 난이도 장벽**: 건축물대장(국토부)+가축사육현황(농식품부/RDA)+기상(기상청)+축산농가(지자체)는 소관 부처가 4개로 분산되어, 공공데이터포털에 데이터가 있어도 "축사 단위로 조인 가능한 매핑키(지번-농가-축사대장 3중 매칭)"를 만드는 실무 지식은 문서화돼 있지 않다. 이 매핑 규칙(완성도 4.3과 연동)이 사실상의 노하우 해자다.
- **신뢰 해자**: 시군 축산과가 "오늘 우선조치 TOP-N"을 실제로 신뢰하려면 최소 1개 시군의 실증 트랙레코드가 필요하다. 익산 선점이 곧 진입장벽이다.

## 4. 완성도

7단계 파이프라인의 4개 취약 관절을 실제 계수·수식·예외처리로 못박아 "숫자를 넣으면 돌아가는 시스템"임을 증명한다.

### 4.1 환기부하 매핑 계수표(재확인, 축종 가중치 추가)

2.4의 등급 A~D(ΔT = −1.5 / +0.5 / +2.0 / +3.0℃)에 축종별 가중치를 곱연산으로 추가 적용: 육계(팬효율 민감도 ×1.2), 산란계(케이지 밀도 보정 ×1.3), 한육우(자연환기 상대적 유리 ×0.8). *RDA 축사시설 환기설계 매뉴얼 개념 준용 — 1차출처 확인 필요.*

### 4.2 트리아지 자원배분 제약식

목적함수·제약식은 3.2와 동일 골격을 실행 레벨로 구체화한다.
1. 차량용량: Σ_i x_i·q_i ≤ Q_v (v=방역차/급수차/쿨러 유형별, 차량대수×1회 적재capacity)
2. 이동시간: Σ_i x_i·t_i ≤ T_shift(시군 1일 가용시간, 예 8시간 방역인력 교대)
3. 동률처리: EL_i 동률 시 두수 많은 순 → 축종 폐사비중(닭88%) 우선 → 접근성(이동시간 짧은 순)
4. 정수제약: x_i ∈ {0,1}

**규모별 solver 전략**: 소규모(≤14시군, 농가 수백 단위)는 그리디+2-opt 지역탐색으로 실시간(초 단위) 근사해, 시군 통합운영 시 MILP(PuLP/OR-Tools)로 정확해 전환. 이유: 자원은 유형별 상이한 capacity를 공유하는 다중배낭문제(multi-knapsack)이므로 랭킹순 배정은 한 자원유형 조기소진 → 적재량 낭비를 유발한다(3.2의 3개축사·2자원 반례 참조). 이 우위는 익산 실증 데이터로 사후 검증한다.

### 4.3 건축물대장-축사 매핑 예외처리

1. **동일지번 다중축사**: 대장을 축사 동(棟)단위로 분할 매칭 실패 시, 두수_동 = 두수_전체 × (연면적_동/연면적_합)으로 대리 추정.
2. **무허가·미등록(대장매칭 실패)**: 등급D(ΔT=+3.0℃) 자동할당 + 위성영상 폴리곤 추출로 위치·규모 보완 + 농협 사육신고자료로 두수 대리(2.7 연동).
3. **용도변경 누락(대장상 '축사' 미기재)**: 익산 실증 매칭률 실측치를 각주 처리하고, 매칭 실패율 자체를 커버리지율 리스크 지표로 시군 화면에 별도 표기 — 결측을 숨기지 않고 정량화한다.

### 4.4 13시군 ETL 최소 데이터요건 체크리스트 및 외삽 방법

1. 기상: ASOS/AWS 관측소-읍면동 최근접 매핑(반경 10km 이내, 결측 시 인접 시군 관측소 대체)
2. 가축사육현황: 시군 집계 두수를 읍면동 비례배분(하위 통계 있으면 우선, 없으면 시군 총두수 × 읍면동 농가수 비중)
3. 건축물대장: 주용도코드 '축사' 필터링 후 구조·승인연도 컬럼 필수
4. 축산농가 위치: 익산 수준 좌표가 없는 12개 시군은 사육현황 행정동 중심좌표로 대체(정밀도 저하 명시)

**외삽 방법**: 익산에서 산출한 등급별 ΔT 보정계수의 예측오차(RMSE)를 축사구조 분포가 유사한 평야형 밀집단지 시군(정읍·김제 등)에 우선 적용하고, 산간지형 시군(남원 등)은 별도 보정계수 재추정 필요를 리스크로 명기한다.

### 4.5 산출물 UX — 신뢰도 배지

"오늘 우선조치 축사 TOP-N + 예상회피손실 + 자원배분표" 화면 하단에 "데이터 신뢰도 배지"(축사매칭 성공/추정/미확인)를 표시해, 담당공무원이 어떤 항목이 실측이고 어떤 항목이 대리추정인지 즉시 식별하게 한다.

## 5. 발전가능성

### 5.1 B2G 계약모델

14개 시군 축산과 대상 연간 구독료: **농가수×2,000원 + 기본료 300만원** 티어. 익산(농가 약 1,400호 가정, 실사 필요) ≈ 580만원/년, 정읍·남원 등 대형 축산시군 800만~1,200만원/년, 소형시군 400만원대. 14시군 합산 1차 B2G 연 매출 목표 약 8,000만~1.1억원. 예산 근거는 전북도·시군 "가축방역비"(재해대응 특별교부세 또는 자체 재해대응기금) 내 "가축전염병예방및질병관리" 세목 중 폭염 대응 신규 세부사업 편성을 전제하되, *이는 가정이며 시군 예산부서 사전 확인 필요.*

### 5.2 B2B PoC 설계

NH농협손보와의 사전 접촉·LOI는 **현재 없음**을 정직히 표기한다. 이를 만들기 위한 선행 PoC: 정읍 또는 남원 소재 산란계·육계 농가 20~30호를 트리아지 개입군(쿨소 알림 기반 우선배치 수령)과 대조군(기존 순번 배치)으로 나눠 2026년 7~8월 폭염기 6주간 실측 비교. 1차 지표=농가당 일일 폐사율 격차, 2차 지표=마리당 기대회피손실(48.36억원/38.3만마리≈마리당 평균 12.6만원 피해단가 환산). 결과를 "손해율 저감 실증 데이터"로 패키징해 2027년 1분기 NH농협손보 제안을 목표로 한다. 즉 "시장 2,200억원"이 아니라 "PoC 결과지 1건"이 채택 경로의 첫 관문이다.

### 5.3 진입장벽 재구성 — 데이터 자산

축사로는 예측 알림만 제공하고 축사 단위 자원배분 실행 데이터를 축적하지 않는다. 쿨소가 익산 즉시실증+13시군 ETL 편입 기간 동안 쌓는 "축사ID×THI\*×실제 개입이력×사후 폐사실적" 페어링 데이터셋 자체가 후발주자가 단기간에 복제 불가능한 자산이다. 익산시·시군 축산과와의 데이터 제공 MOU(익산 실증 단계에서 체결 목표)를 진입장벽의 핵심 근거로 삼되, *익산시 MOU는 목표 단계이며 현재 미체결임을 정직 표기.*

### 5.4 비수기(한파) 수평확장 — 계절 헤지 수익모델

폭염 트리아지(7~8월 성수기) 구독료의 60~70% 수준 별도 요금제(한파 트리아지, 12~2월)를 동일 고객(14시군 축산과)에게 추가 판매. THI 대신 축종별 저온 스트레스 지수(육계 체감온도 지수, 한육우 Cold Stress Index)로 위험강도 항만 교체하고, 트리아지 최적화 엔진·건축물대장 구조보정 로직은 재사용한다(한계비용 낮은 2차 매출). 연 매출을 여름 단일 시즌 대비 약 1.6~1.7배로 확장하는 시나리오.

### 5.5 3단계 로드맵 및 리스크 정직 표기

1차(1~2년차) B2G 구독 매출 확보 + 익산 레퍼런스 데이터 축적 → 2차(2~3년차) NH농협손보 PoC 실행, 손해율 저감 실증치 확보 → 3차(3~5년차) 실증치를 지수보험 언더라이팅 파라미터(마리당 기대손실 신뢰구간)로 이전, 가축재해보험 연 2,200억원 시장(부보 17~19조·가입률 94~96%, 전북 피해 88%가 가금) 중 성과수수료(gain-share) 형태로 참여.

*리스크 각주*: ① NH농협손보 등 보험사와의 사전 접촉·LOI는 현재 없으며 상기 로드맵은 가정된 시나리오임. ② 시군 구독료·예산 계정과목은 전북도·시군 예산부서 확인 전 추정치임. ③ 익산시 MOU는 목표이며 미체결.

### 5.6 선택적 확장 옵션(간결 언급)

- Boiler Bid형 자원조달 확장: 트리아지가 "누구부터 구할지"에 답한다면, 수소상용차 폐열·유휴적재 등 외부자원의 역경매 동원으로 "무엇으로 구할지"를 보강하는 옵션(제품화는 후순위, 언급 수준).
- FEER형 전력 리스크 흡수: 냉방부하 급증에 따른 정전·전력요금 리스크를 트리아지 가중치의 보조변수로만 흡수(별도 제품화 없음).

## 6. AI혁신성

쿨소의 AI는 3개 층으로 구성되며, **THI 및 축종별 보정계수 계산은 결정론적 물리식(비-AI)이고 AI 요소는 오직 확률추정층과 최적화층 두 곳뿐이다.** THI는 입력이지 AI가 아니다.

### 6.1 층0(비-AI 물리식): 가금 특화 THI

표준 THI = (1.8T+32) − (0.55−0.0055·RH)(1.8T−26.8)는 소(牛) 기준이며, 폐사 88%가 닭인 전북 현실과 괴리된다. 쿨소는 축종별 열스트레스지수를 분기한다.

**THI_species = THI_std × k_species + b_species**

| 축종 | k | b | 임계 THI_c |
|---|---|---|---|
| 육계(broiler) | 1.15 | +2.0 | 27 (관용범위 좁음) |
| 산란계(layer) | 1.08 | +1.0 | 28 (산란율 저하가 선행지표) |
| 오리(duck) | 0.92 | −1.5 | 30 (상대적 내서성) |
| 한육우(beef cattle) | 1.00 | 0 | 72 (표준식 원 스케일 유지, 별도 정규화 필요) |

*RDA 가금연구소 사양관리지침 반영 예정 — 계수·임계치는 제출 전 1차출처 확인 필요.* 이 계수는 가축사육현황(15021089/15072592)의 축종 필드로 자동 분기 적용된다(2.5 연동).

### 6.2 층1: 확률추정 — 2단 베이지안의 완전한 통계모델화

축사단위 폐사 라벨이 없는 상황(라벨부재)에서 "몇 마리가 위험한가"의 신뢰구간을 역추정하는 문제다.

**Step A(사전분포 파라미터화)**: RDA/NIAS 폭염 가축 생산성 저하 곡선에서 THI 구간별 폐사율 평균(μ)과 분산(σ²)을 모멘트 매칭으로 Beta(α, β) 모수로 역산한다.

α = μ(μ(1−μ)/σ² − 1), β = (1−μ)(μ(1−μ)/σ² − 1)

예: THI 80~85 구간 육계 폐사율 prior 평균 2.1%, 분산 0.0004 가정 시 α≈11.5, β≈536. *RDA/NIAS 보고서명·연도·표본규모는 제출 전 1차출처로 확정 필요, 현재는 가정치.*

**Step B(우도함수)**: 시군 단위 관측 폐사마릿수 D_j ~ Binomial(N_j, p_j), N_j=가축사육현황 사육두수.

**Step C(추정 알고리즘)**: 축사단위 p_i에 건축물대장 구조계수(2.4)를 보정하면 시군집계 우도와의 비선형 결합으로 폐쇄형 해가 사라진다. 이에 **ABC-SMC(Approximate Bayesian Computation - Sequential Monte Carlo)**를 채택한다: (1) prior에서 p_i 샘플 (2) 축사구조 보정 적용 (3) 시뮬레이션된 시군 총 폐사마릿수와 실측치의 유클리드 거리 ε 이내만 채택 (4) ε을 단계적으로 축소. **MCMC 대신 ABC를 쓰는 이유**: 축사단위 우도가 관측 불가(라벨부재)한 likelihood-free 상황이며, 이는 ABC가 정확히 설계된 조건이다.

**대안 경로**: 익산 실증 초기 표본희소성이 극심한 구간에서는 ABC-SMC 대신 계층 로지스틱 회귀(시군을 random effect로)를 변분추론(mean-field VI, ADVI/PyMC 구현)으로 근사해 계산비용을 낮춘다. 두 접근 모두 "데이터 희소성에 강건한 설명가능 통계접근"을 의도적으로 선택한 것이다.

### 6.3 층1-부속: 카운터팩추얼 — 인과추론 프레임 한정

구조적 인과모형(SCM) 전체를 주장하지 않고, 검증 가능한 단일 개입변수(송풍기 설치 유무)로 실증범위를 한정한 **이중차분(DID)** 설계를 채택한다.

폐사율_it = β0 + β1·Treat_i + β2·Post_t + β3·(Treat_i×Post_t) + ε_it

β3(교차항 계수)이 개입효과(ATT). 실증가능 사례: 2024년 여름 송풍기 신규설치 농가군(treatment) vs 미설치 인근 유사규모 농가군(control)의 폭염 전/후 폐사율 변화 비교 1건으로 한정한다. 병행추세가정(parallel trend) 검증을 위해 개입 이전 시계열(2023년 동기간) 추세 비교를 전제조건으로 명시하고, control 선정 시 성향점수매칭(PSM, 사육두수·축사구조·지역 공변량)을 보조수단으로 사용한다.

### 6.4 층2: 조합최적화 — 트리아지는 argmax 한 줄이 아니다

목적함수: max Σ_i x_i·L_i (L_i = p_i×N_i×단가 − 개입후 예상p_i×N_i×단가, 베이지안 사후분포에서 도출)

제약식: Σ_i x_i·c_i ≤ V(자원 총capacity), Σ_i x_i·t_i ≤ T_shift(가용시간), Σ_i x_i ≤ K_vehicle(차량대수), x_i∈{0,1}, 동률 시 이동거리 최소 우선(그리디 타이브레이크).

정확해가 필요한 야간 배치계획(1일 1회)은 0-1 정수계획법(ILP, PuLP/CBC)으로, 실시간 현장 재배치(폭염특보 급변)는 그리디+2-opt 지역탐색 근사해로 이원화한다. **규칙기반 랭킹이 아닌 이유**: 단순 랭킹(회피손실 내림차순)은 자원용량·이동시간 제약을 위반해 실행불가능해를 반환할 수 있지만, ILP/그리디+지역탐색은 제약충족 하 총회피손실을 최대화하는 조합해를 보장한다(3.2의 수치 반례 참조).

### 6.5 hold-out 검증 계획 및 성능지표

**학습**: 2024년 데이터(THI 시계열 + RDA prior + 2024 시군별 최종 폐사통계 38.3만마리/890농가)로 Step A~C 사후분포 추정.
**검증**: 2025년 실측치(잠정 16.6만마리, 최종 확정 시 갱신)를 hold-out으로 사후예측검사(posterior predictive check) 수행.

| 지표 | 정의 | 성공기준 |
|---|---|---|
| 캘리브레이션 | 예측확률 구간(0-10%,10-20%...)별 실제 폐사율 일치도 | 플롯 시각 점검 |
| Brier Score | (1/n)Σ(예측확률−실제발생)² | < 0.05 |
| 순위상관(Spearman ρ) | 예측 고위험 시군 랭킹 vs 실제 피해순위(정읍·남원·익산·김제) | ρ > 0.7 |

### 6.6 각주 처리 원칙

RDA/NIAS 감소율곡선 출처(보고서명·연도·표본수), 축종별 THI 임계치, 축사로/민간 스펙 인용은 모두 "제출 전 1차출처 확인 필요"로 각주 표기하되, 위 수식·알고리즘 구조 자체는 특정 수치가 교체되어도 논리적으로 자립하도록 설계했다.
